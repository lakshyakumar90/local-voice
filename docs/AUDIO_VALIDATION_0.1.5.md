# Audio and build validation — 0.1.5

26 October 2026. These results distinguish formatting/insertion policy from recognition accuracy. The audio runs were local desktop inference, not Android microphone or phone tests.

The final raw Small results still contain incorrect words and spellings. No formatting rule can establish the missing intended words. These two clips do not demonstrate reliable general Hindi accuracy, and no such claim is made. Orthographic WER uses NFC-normalized, lowercased letter/mark/number words and edit distance, ignoring punctuation. Splitting a compound or changing script counts as errors; ratios above one are possible when there are extra words. No translation or phonetic normalization is used to improve the metric.

## Build and policy verification

The final combined core tests, app unit tests, debug assembly and lint command succeeded in 1 minute 44 seconds. **52 JVM tests pass**, including four tests over actual captured audio hypotheses; none were skipped in that run. Lint reports zero errors and 16 existing/dependency/style warnings. A separate native policy test passes checks over 2,431 Unicode code points, mixed/split byte pieces and desktop-regex equivalence. The ten-minute bound, scaled processing/target budgets, pure-break insertion, text preservation, language preservation and rejection behavior have automated coverage.

The APK verifies its signature, 16 KB ZIP alignment and every packaged native ELF's LOAD alignment. Package dev.localvoice.app, versionCode 6, versionName 0.1.5; ARM64 and x86_64. Signing certificate matches the preceding debug upgrades. This is a debug APK; no new minified release or Play/device review is claimed.

There is no connected Android phone/emulator. Ten-minute capture, thermal/battery behavior, memory under the chosen model, real accessibility/IME insertion and rendered Android layouts remain phone checks. The native input cap and UI are ten minutes, but the full ten-minute microphone lifecycle was not exercised here.

## Reproduction and attribution

Captured raw text and provenance are committed under core/src/test/resources/audio-smoke. Default JVM tests replay those real hypotheses through the current formatter and rejection policy; they do not rerun native ASR. A fresh inference pipeline can be supplied with -PaudioSmokeDir. Source audio, model weights, environment and inference reports remain ignored work files.

Desktop: pywhispercpp 1.5.1, CPU, one thread for English and two for Hindi comparison. Language/task/sampling and constrained Hindi token policy match the app; native build, thread count and operating system differ. The desktop exclusion regex has equivalent byte semantics to the app's precomputed callback; its timings should not be used as phone performance estimates.
