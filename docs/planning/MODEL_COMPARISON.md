# Local model and runtime comparison

Accessed 2026-10-25. **No Android inference, latency, memory, accuracy, or energy measurement was performed.** Published desktop or dataset scores do not establish phone performance. Sizes below are source metadata, upstream rounded figures, or explicitly unknown; model size excludes runtime libraries, tokenizer files unless stated, native workspaces and application memory.

## Recommendation

For a plain-language release roster and a model-by-model explanation of the user's Handy screenshot, see [Model selection](MODEL_SELECTION.md). That supplement adds verified Nemotron 3.5 Hindi coverage and distinguishes staged initial downloads from later experimental families; it does not expand the shipped registry without the stated gates.

1. **whisper.cpp + multilingual Whisper Base Q5_1** is the default first engine/model. Its Android example is established, the artifact is 59,707,625 bytes, it covers Hindi and English, and its runtime/weights have permissive MIT terms. Offer Tiny Q5_1 as an explicit lower-resource option. Compare FP16 and Q5_1 accuracy before committing to the quantized default. Small Q5_1 is optional after measurement.
2. **Moonshine Voice + Tiny Streaming English**, quantized ORT asset set `tiny-streaming-en/quantized_26_08_21`, is the second, genuinely different engine. It has Java/JNI Android integration, ~45.23 MB required model components, streaming capability and MIT English weights. It is English-only; Hindi/Hinglish stays on Whisper. Version/API parity, cryptographic artifact manifest, 16 KB libraries and device results gate shipping.
3. **Silero v6.2.0 VAD through whisper.cpp's independent VAD C API** avoids a new runtime in Phase 1. Keep the VAD interface independent of ASR so the same detector can assist Moonshine. Do not instantiate two competing endpoint controllers. Manual stop remains authoritative.

## VAD evaluation and segmentation

VAD decides likely speech boundaries; it does not identify language, transcribe, punctuate or improve vocabulary. Silero accepts 8/16 kHz upstream; select 16 kHz and verify 512-sample frame behavior in the pinned C API. [Silero documentation](https://github.com/snakers4/silero-vad) publishes tiny desktop compute figures; those are not Android guarantees.

Start with threshold 0.3, 450 ms context padding, and a 1.2 s candidate end-of-speech pause. These are proposed tuning values. Never auto-stop the entire session on natural silence. At explicit stop, process padded outer speech bounds with internal pauses preserved. Preserve the original bounded in-memory PCM until the result is accepted; an empty ASR result after VAD cropping gets one full-audio retry. Avoid aggressive internal silence deletion or segmentation in the initial two-minute batch path. Moonshine consumes continuous audio and manages its own stream; external VAD may suppress truly empty sessions but must not reset its decoder on every natural pause.

Compare against VAD disabled and WebRTC VAD on low-volume speech, breathy voices, fans/traffic, music, short words and 0.5–3 s thinking pauses. Measure false rejection, clipped initial/final words, false-speech duration and incremental energy. If VAD harms completeness, disable cropping; recognition must still function without VAD. Earshot is a Handy alternative, but its Rust dependency and new Android integration offer no proven advantage here.

## Benchmark experiment

Follow the device/corpus procedure in [Roadmap](IMPLEMENTATION_ROADMAP.md). Benchmark identical PCM, language mode, decode settings, threads, model/runtime revision and thermal state. Compare W-B FP16/Q5_1, W-T Q5_1, W-S Q5_1, and M-TS on the same English panel; include V-HI as a research comparator only if Hindi targets fail. Do not rank Moonshine's leaderboard WER against Whisper's phone results from different datasets.

Report p50/p95 load, speech-to-partial, stop-to-final, end-to-end insertion, full-clip real-time factor, CPU, whole-app/native PSS, APK/AAB compressed and installed bytes, model bytes, energy and thermal change. Cold and warm runs are separate. Publish raw records and confidence intervals, including failures. Quantization must be checked for Hindi/Hinglish quality regression, not just file reduction.
